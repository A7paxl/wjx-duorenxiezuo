# 协作契约

全员共同遵守。规则只有统筹一人能改；改动发公告。

## 1. 两个仓与所有权

- **公共仓**：全组共用、全员可见；装入口、成员与规则、推进管理、交换区、知识区、工具箱、归档。
- **个人仓**：每人一个；装个人过程、任务包、草稿、个人生效区、`05-单据` 副本、日志；远端只有本人有权限。
- 本试点工作区有 1 个公共仓 + 2 个个人仓：`个人仓/甲`、`个人仓/乙`；真实项目每人一个个人仓。
- 公共仓全员可见；个人仓之间互相不可见，每个人只能看自己的个人仓；个人仓之间只通过公共仓交换区的出件箱/收件箱接收内容。

| 区域 | 谁写 |
| --- | --- |
| 公共仓 `00-入口`、`01-成员与规则`、`02-推进管理`、`04-知识区`、`05-工具箱`、`06-归档` | 统筹；脚本产物由脚本写 |
| 公共仓 `03-交换区/出件箱/<姓名>` | 本人 |
| 公共仓 `03-交换区/收件箱/<姓名>` | 投递脚本 |
| 公共仓 `03-交换区/交换台账.md` | 投递/回执/退回脚本 |
| 个人仓 | 只有本人；`05-单据` 只放副本 |

## 2. 写入边界

- 任何人不得改别人个人仓里已有的文件。
- 跨区只投递新文件：正件留发起人公共仓出件箱；接收人公共仓收件箱只放一条指向消息；个人仓 `05-单据` 只放副本。
- 公共仓的规则、当前推进、决策记录、静态知识、归集产出由统筹/脚本写；成员要改，向统筹提案。

## 3. 单据

- 三种：协同单（委托产出 / 请求确认 / 请求裁决）、回执、退回单。
- 命名五段：**日期-发起方-接收方-主题-类型**；脚本据此判定单据状态。
- 发起人收口：谁发单谁验收；产出经使用方确认后才归集。
- 退回必须写原因、依据和替代做法（如能给）；改投用新单。
- 投递四动作：写出件箱（正件+材料副本）、写收件箱（指向消息）、提交推送公共仓、触发钩子（台账/看板/通知）；全成或全不成。
- 单据模板给 AI 起草前预检：投给谁、谁确认、是否涉密、确认后写回哪里。

## 4. 个人仓

- 装个人过程、任务包、草稿、个人生效区、`05-单据` 副本、日志。
- 单据正本和收件箱在公共仓交换区；个人仓不设出件箱/收件箱。
- 个人稿不确认不生效；个人生效版本替换前，旧版先进 `04-归档/`。

## 5. 公共仓的个人工作台

- 每人的工作台在 `02-推进管理/工作台/`，由 `同步工作台.py` 从个人仓任务状态生成。
- 工作台只放状态、阻塞、产出位置、更新日期；不放草稿、不放保密数值。
- 工作台供外圈、业务方、评审查看；个人仓仍是过程源。

## 6. 生效与归集

- 个人生效：本人确认；旧版进个人 `04-归档/`。
- 全组生效：发起人验收后，`归集.py` 写入 `04-知识区/current/`；同名旧版先进 `history/`。
- 同一内容全空间只有一个 current 版本；history 只增不删，AI 默认不读。

## 7. git 规则

- 一个公共仓 + 每人一个个人仓；个人仓远端只有本人有权限。
- 收工只推个人仓；公共仓由投递/归集/统筹更新。
- 提交说明：`成员 任务：动作`；不强制推送共享分支。
- 聊天、邮件、会议里的决定，必须写进仓库文件才算数。

## 8. 公告

- 规则只有统筹能改；任何规则文件改动，都在 `00-入口/公告栏.md` 发宣告，写明改了哪份、生效日期、影响谁。
- 真实环境由钩子推全员京ME；本试点只写公告栏。

## 9. AI 规则

- AI 只读公共仓 + 本人个人仓 + 输入清单；别人的个人仓不读。
- AI 只写本人个人仓；公共仓的写入走脚本或统筹。
- AI 不得在人确认前让草稿生效；不得把保密数值写进公共仓。

## 10. 入组与离组

- 入组：统筹在名册登记 → 本人在自己机器上建个人仓 → 读公共 AGENTS + 本仓 AGENTS → 领任务。
- 离组：归档收件箱和未完成任务，交接给统筹；个人仓保留只读。
